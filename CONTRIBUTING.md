# Project Working Agreement

1. Create an issue for each feature, defect, or documentation task.
2. Define testable acceptance criteria before implementation.
3. Use a branch for meaningful changes and a pull request where practical.
4. Test happy paths, invalid inputs and empty states for changed features.
5. Update the RTM and test evidence when requirements or behavior change.
6. Never commit API keys, `.env` files, personal data or confidential information.
7. Do not mark work complete until the Definition of Done in `docs/AGILE_WORKFLOW.md` is met.
